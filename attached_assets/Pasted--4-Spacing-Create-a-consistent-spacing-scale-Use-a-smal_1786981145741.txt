## 5. Layout

The application is mobile-first.

Define:

- Page margins
- Content width
- Grid behaviour
- Card spacing
- Section spacing
- Bottom navigation spacing
- Safe areas for mobile devices

The interface should be comfortable to use with one hand while training.

- Success

- Pressed
- Disabled

Use one consistent icon free to access library throughout the application.

Define global design tokens for:

- Border radius

- Shadow/elevation

## 15. Responsive behaviour

The design system should work across:

- Mobile
- Tablet
- Desktop

However, mobile is the primary experience.

Workout screens should remain optimised for mobile even on larger screens.

## 16. Accessibility

Follow accessible design principles.

Include:

- Sufficient colour contrast
- Visible focus states
- Appropriate touch target sizes
- Semantic HTML
- Accessible labels
- Keyboard navigation where appropriate
- Screen-reader-friendly components

## 17. Component architecture

Build these as genuinely reusable components.

Do not duplicate styles across individual screens.

Use shared design tokens for:

- Colours
- Typography
- Spacing
- Radius
- Shadows
- Breakpoints

Components should be easy to reuse and modify later.

## 19. Important constraints

Do not add unnecessary functionality.

Do not change the underlying workout logic.

Do not change the database schema unless absolutely necessary.

Do not remove existing features.

Focus on establishing a consistent visual language and reusable component system.

Before making major architectural changes, explain what you intend to change and why.

At the end, explain:

1. What design tokens you created
2. What reusable components you created
3. Where they are stored in the project
4. How future screens should use them
5. How I can change the global visual style later
